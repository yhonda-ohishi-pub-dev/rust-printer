## 実施内容

### 1. 印刷テスト実施・原因追及

#### 問題
- RAW TCP (ポート9100) で印刷リクエスト送信後、プリンタキューで「待機中」「0 x 0 / 1」となり印刷されない
- 同じPDFを `nc` コマンドで送信すると正常に印刷される

#### 原因
**Dockerコンテナのネットワーク分離**が原因だった。
- コンテナはブリッジネットワーク (172.21.0.0/16) 内にいた
- ホストの `172.18.21.60` とは別ネットワーク
- 接続自体は成功するが、実際のデータ到達に問題があった

#### 解決策
`docker-compose.yml` に `network_mode: host` を追加してホストネットワークを直接使用。

```yaml
services:
  rust-app:
    ...
    network_mode: host  # 追加
    # ports: は削除（host modeでは不要）
```

### 2. TCP shutdown() 追加

印刷速度改善を期待して `shutdown()` を追加したが、効果なし。
ただしコードはそのまま残している。

```rust
// rust-app/src/print/ipp_client.rs
stream.write_all(&pdf_data)?;
stream.flush()?;
stream.shutdown(Shutdown::Both)?;  // 追加
```

### 3. フォントサブセット化の調査

#### 現状の問題
- PDFサイズが約6MB（フォント ipaexg.ttf が5.9MB）
- プリンタ側でのPDF処理に時間がかかる

#### 調査結果
- printpdf 0.8 でサブセット化機能がサポートされている
- しかし 0.7 → 0.8 で API が大幅に変更されており、移行には generator.rs の全面書き換えが必要

#### printpdf 0.8 での主な変更点
- `PdfDocument::new()` の引数が変更（4引数 → 1引数）
- `PdfLayerReference`, `IndirectFontRef` 等の型が削除/変更
- `Line` 構造体の `points` フィールドの型が変更
